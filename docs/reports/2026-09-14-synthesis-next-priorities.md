### Keep the next milestone bounded

For Exference kinds, retain ownership by lexical binder slot across freshening and substitution; a map keyed only by reused source identifiers cannot distinguish shadowing or provider-local binders. Check selected type kinds and quantified-type compatibility in the independent checker as well as search. Existing shared source-kind transport is a reuse candidate, while a rewrite of the accepted Djinn implementation needs a demonstrated requirement. A successful first public case earns expansion to the remaining ten; a failed design must identify its first lost obligation before another abstraction layer is added.

Integer `at` has no dependency on Exference's explicit source-kind implementation. If the kind experiment fails its stated gate, record the concrete reason and run the existing native integer baseline before attempting another broad kind redesign. Keep the index as `Int`, supply the agreed default, and test negative, zero, valid and out-of-range positions. An unindexed native result is unknown until that baseline establishes it.

Treat native adoption of the already published Djinn prefix repair as release maintenance: Leant currently pins `9a2d59d9`, while Djex root includes the later repair. Update the pin only with affected native integration checks on the proposed dependency. If another accepted engine milestone will immediately change that dependency, combine the integration once; do not present the current pin as containing the later fix.

## Acceptance and stopping rules

Selected polymorphic types must preserve lexical scope, capture avoidance, visibility and actual universe formation. Nominal/class identities must distinguish their structured declarations and normalized level selections; global providers must instantiate declaration-owned universes from source evidence. Printed binder names are not ownership evidence. Lean's predicative universe hierarchy remains authoritative even when the corresponding Haskell signature uses impredicativity.

Each new source gate must require the selection being tested, rather than merely admit an unrelated inhabitant. Exercise ordinary and named-function `where` queries, each individual engine and Both where supported, independent exact replay, and actual-False or malformed-source controls. A Both result cannot establish either individual engine's success. For partial Church functions, retain supplied defaults or inhabitance assumptions in Lean.

The [behavior ledger](../../test-church/behavior-ledger.md) is unchanged: **94 historical acceptances, 23 attempted cells without indexed acceptance and 43 without indexed evidence**. The 66 cells without indexed acceptance comprise 15 reductions, one Lean Djinn `length`, five integer-`at` and 45 extrema cells. They are evidence categories, not a current pass rate or a count of proven missing capabilities. The source obligations above are additional. The dictionary milestone closes no Church behavior cells.

For each implementation: establish the discriminating query, repair the first demonstrated loss, run the affected family and appropriate release checks, then publish a stable milestone to both repositories with a coherent native dependency pin. A bounded miss is inconclusive, not a proof of non-inhabitation. Stop a failed hypothesis when its discriminating experiment fails; require new evidence before spending another larger search budget.
