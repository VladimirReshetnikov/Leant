# Further improvements after native contextual integration

This assessment replaces the delivery order in the [previous re-triage](2026-09-09-synthesis-after-one-shot-acceptance.md). The deadline repair and canonical contextual integration are accepted milestones and leave the active implementation queue. The next work should close contextual data construction, deliver missing Church behaviors, and then expand public syntax and provider evidence in bounded increments.

The original priorities 1–4 remain in force. This report changes the order of work, not the meaning of practical rank-N and impredicative support or the agreed treatment of partial functions.

## Evidence that changes the priorities

- **Native integration is closed.** The [integration report](2026-09-09-one-shot-native-integration.md) and its immutable receipt record ten fresh passing gates at Djex `3adfac5c57ad5e1bec77c598c647f6c8eb38e6e6`: 705 unit tests, both 350-signature native corpora with axiom-free kernel replay, contextual/provider checks, native List recursors, and all 13 extended Lean Exference operations. The receipt has no pending gates. Earlier interrupted attempts remain historical; they are not current blockers.
- **The documented Haskell contextual matrix is accepted.** The [canonical report](2026-09-09-one-shot-contextual-output.md) records 2,371 tests in 16 suites, 64 public queries and 5,354 displayed alternatives independently compiled and evaluated. These are alternatives, not a count of distinct programs. That evidence does not cover every remaining frontend form.
- **The list issue is more specific than a general rendering failure.** Local first-selection probes compile basic contextual list output in both Haskell engines. A behavioral query requiring a nonempty list containing the caller's selected method exposes a Djinn construction miss: its original contextual plan offers only the empty-list result. A local repair supplies visible constructors through the existing checked provider-rewrite boundary, and the singleton probe then succeeds in Djinn, Exference and Both. This is an experiment, not an accepted production milestone.
- **Public-output extraction is itself a validation obligation.** The new focused list regression can report “no matching contextual list” even when the transcript contains a lambda expression and a successful behavioral observation: its extractor recognizes only a named definition or an expression beginning with `(`. The exact emitted expression still needs independent full-signature replay. A harness failure must not be reported as a search miss, and a successful behavioral observation must not be promoted to complete output acceptance.
- **Exference has a separate residual evidence failure.** In the polymorphic-element case, first/best find a behavioral success, but the False query's candidate pool contains compilation errors; sampled retries report `HaskellGraphRootSignatureRequired`. All-selection also exposes these errors in its positive pool. Thus the stronger test fails its error-free control requirement even though no False candidate is accepted. Investigate missing root-signature evidence separately from output extraction; do not describe this as either unsound acceptance or failure to find any implementation.

The local constructor change and new tests remain outside the published production revision. Their evidence supports the next investigation; it does not extend Leant's accepted dependency. A broader recursive-type expansion was tried and withdrawn after it changed an existing conservative-bound regression. There is no justification here for globally relaxing recursive expansion or search limits.

The focused run finishes with **nine failing tests in 254.57 seconds, exit 1**. Djinn and Both fail output extraction; Exference fails the error-free False-control requirement, and Both also records those candidate errors. These are nine test failures, not nine synthesis misses. The [diagnostic receipt](https://github.com/VladimirReshetnikov/Djex/blob/main/test-integration/receipts/native-contextual-retriage.json) and [archive](https://github.com/VladimirReshetnikov/Djex/blob/main/test-integration/receipts/native-contextual-retriage.zip) retain the terminal transcript, local source/test patch, probe inputs/outputs and packaging-time executable hashes. They are explicitly diagnostic artifacts, not acceptance receipts; the full suites and native integration have not been rerun for the experimental change.

## Unchanged completion boundary

The Church behavior objective remains **(13 extended + 19 supplied-default operations) × (2 Haskell engines + 3 Lean modes) = 160 cells**. Negative controls and independent replays are additional. Partial Lean counterparts retain a supplied default or inhabitance assumption; ordinary behavioral queries retain the named-function-plus-`where` syntax.

Accepted signature inhabitation, ordinary structures, native List recursors and canonical Haskell Exference tree synthesis remain regression obligations at their recorded revisions. Native tree synthesis is still unaccepted in all three modes. Neither these finite tests nor this re-triage establishes complete higher-rank inhabitation search. The wider implementation goal remains active.
