### Next discriminating cases and release boundaries

1. Exercise unused higher-kinded binders publicly, both at the root and in local callbacks. The current successful signatures constrain kinds through applications; they do not test whether a generated local annotation accidentally defaults an unused binder to `Type`.
2. Exercise shadowed and adjacent, same-shaped binders with different kinds, plus invalid selected type arguments. Private checker coverage exists; public source reconstruction must preserve the same distinctions.
3. Expand a source synonym containing an unused kinded binder and select higher-kinded arguments in a minimal environment. This tests expansion and availability of valid instantiations independently of the nominal constructors supplied by the private fixtures.
4. Exercise a nested or impredicative result and one constrained callback. Follow any reached alpha-equivalence or evidence comparison that could erase kind ownership; retain exact selected dictionary identity.
5. Run the relevant private, request, public API and ordinary-query regressions against the final integrated source. Transport only the validated source slice, package replay evidence, and validate the corresponding Leant dependency update before changing its pin.

These are release gates, not confirmed defects. A failed case should identify the specific loss of scope, kind, construction or rendering.
