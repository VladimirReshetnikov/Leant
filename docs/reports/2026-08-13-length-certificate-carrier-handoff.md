Date: 2026-08-13

## Outcome

Leant pins Djex commit `6653fb4b`, which extends the original associated
provider-certificate consumer with occurrence-specific ground constraint
discharge. Production still passes the complete opaque Exference typed
candidate through `Leant.Synth.Length.Handoff`; it does not project a graph and
try to recreate authority. On the context-free compatibility path, productive
exact assignments continue to reach the associated candidate before the legacy
plain fallback. Exact contextual vectors with selected fact groups do not enter
that assignment adapter; a no-group exact-evidence provider instead recovers
its successfully translatable bounded vectors through the erased fallback. The

conditional occurrence remains Length-ineligible.

This remains deliberately different from projecting
`typedCandidateTermGraph`. Rendering may use that public bare graph as an
observation, but a stamped projection has lost its certificate association and
Djex's public shared-graph fingerprint rejects it. The whole candidate lets
Djex freshly re-seal the graph with the exact Length session schema, authorize
every rooted association row, audit protected provider prefixes, and only then
interpret the graph.

## Admitted authority

Every associated row must name the exact source-inventory owner, retain an
alpha-exact complete source scheme, and resolve to the checked Length provider
summary co-sealed by the same session. Modeled zero/step constructors remain
unsupported as certificate owners. A detached stamped graph cannot recover any
of this authority.

There are now two exact provider paths:

- the legacy context-free summary still requires empty activated obligations;
  and
- a constraint-conditional summary requires a nonempty activated context,
  successful static ground discharge for every obligation, and an intact
  protected certificate chain. Only that row's final receipt-bearing
  visible-application node may invoke the assumed provider transfer.

Leant makes the second path reachable without weakening the selected Exference
source scheme. Its live provider wire retains supported instance-implicit
binders as bounded semantic exact contexts; Exference preserves them on the
plain/binder-only and accepted-fact lanes, while a no-group exact-evidence
provider takes its erased fallback. Dependent, open, or unsupported contexts
fail closed instead of being erased. Djinn keeps its
historical context-erased positive-search compatibility projection and never
owns this carrier. Only a complete exact live `(instantiations ...)` vector
established by top-level Lean active-instance closure can contribute synthetic
zero-binder, zero-prerequisite ground facts to the exact Exference/Length
inventory. The complete specialized constraint group must pass a clean replayed
trial inventory seal. The historical `(candidates ...)` form has its source
context erased in both projections and cannot contribute such facts.

Those derived facts have exact-inventory scope. Although the assignment vector
remains provider-local for candidate specialization, a ground fact may discharge
a matching obligation belonging to another provider in that inventory: Lean
established it from the global top-level instance environment and closed the
complete prerequisite chain, not from a query given or a provider-local
dictionary. Djex then independently resolves the activated ground constraint
under its session-owned bounded static resolver. Neither Leant nor Djex retains
or replays the frontend dictionary term.

There are no query givens in this discharge path. Z3 runs only after the exact
candidate has sealed a checked Length problem and cannot establish a class
fact, choose a dictionary, or repair a failed certificate chain. Solver status
remains heuristic until exact problem-bound counterexample replay succeeds.

The current Leant bridge and its provenance boundary are detailed in the

The three session-policy and concrete versions correspond to ordinary or

session, problem, query, and protocol identities bind the selected components
transitively, so conditional values cannot collide with legacy cache keys.

Provider and semantic retention, session policy, and concrete encoding switch
even when the retained conditional summary is unused. Candidate v3 is narrower:
it requires an actually authorized, statically discharged association; an
unrelated candidate in the same session remains v1 or v2. No public key contains
a dictionary, resolver proof, discharge receipt, or certificate coordinate.

## Regression and compatibility

The polymorphic context-free provider path remains the compatibility control.
Its projected bare graph receives the exact public unsupported-certificate
refusal, while the original whole candidate passes callback verification and
the production Length handoff with the checked provider law.

The conditional path additionally retains a contextual provider scheme, exact
top-level assignment evidence, its derived ground fact, and the activated
certificate obligation. Production Handoff must classify the provider summary
as conditional and Djex must discharge the obligation before a checked problem
or canonical QF_LIA query can exist. The regression explicitly selects the
certified candidate from the Exference lane rather than the ineligible direct
conditional occurrence. Its fake-Z3 trace starts at query ordinal 0, issues no
`get-value`, and replays a zero-input, result-0 counterexample whose
`FiniteSpineModelUnderAssumedProviderLaws` basis names the exact provider.
Controls without exact live provenance, with unsupported contexts, or with only
legacy candidate hints remain fail-closed.

This extension changes the live provider wire and exact synthesis inventory,
but not the user contract grammar, ranking rule, rendered Lean term syntax,
SMT-LIB lowering, or public graph authority. Every rendered synthesis candidate
still passes Lean elaboration and kernel checking; every behavioral solver
observation still passes the existing problem-bound replay boundary.
